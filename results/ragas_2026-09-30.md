## What was run

- Command: `python -m eval.ragas_eval --fake` (also `make ragas-eval`; CI `backend` job).
- Golden set: `eval/datasets/ragas_golden.jsonl`, 12 questions written for this eval
  (8 methodology notes, 4 published book figures), each with a ground truth and the
  expected source document.
- Answer path: mirrors `backend/app.py` `chat()`: input refusal policy, top-4 retrieval from
  a FAISS index over the same corpus `ingest.py` builds (21 chunks), keyword-routed book docs
  prepended, same system prompt and message shape, output filter.
- Runtime: about 1.5 s on the dev Mac, offline.

How to read it:

- `faithfulness` is 1.00 by construction: the fake answerer copies sentences out of the
  context, so every claim is in the context. It shows the metric plumbing works, nothing more.
- `answer_relevancy` is low because the fake "regenerated question" is a bag of the answer's
  content words, compared with hashed embeddings. It is not a semantic score.
- `context_precision` below 1.0 on r01, r04, r05, r06 means the note holding the answer was
  retrieved but not ranked first under the hashed embedder (e.g. the Sharpe note ranked 4th).
- `expected source retrieved` = the expected document was in the context the answerer saw.

## Why a local mirror and not the `ragas` package

Attempted 2026-09-30 in the repo venv (Python 3.13.11, macOS Intel):

```
$ pip install "ragas<1"        # resolves ragas 0.4.3, langchain-community 0.4.2, openai 1.109.1, ...
Successfully installed ... ragas-0.4.3 ...
$ python -c "import ragas"
  File ".../ragas/llms/base.py", line 12, in <module>
    from langchain_community.chat_models.vertexai import ChatVertexAI
ModuleNotFoundError: No module named 'langchain_community.chat_models.vertexai'
```

The install also downgraded shared packages (`protobuf` 7.36.2 -> 6.33.6, `rich` 15 -> 13.9.4,
`tenacity` 9.1.4 -> 8.5.0), leaving `grpcio-tools` (via qdrant-client) with an unmet
`protobuf>=7.35.1`. LangGraph 1.x needs langchain-core 1.x, and the langchain-community that
resolves next to it no longer ships the module ragas 0.4.3 imports. So `ragas` was uninstalled,
the downgraded packages were restored, and `ragas` is **not** in the `dev` extra.

`eval/ragas_eval.py` implements the four metrics following the RAGAS definitions:

| Metric | Definition used |
|---|---|
| faithfulness | answer claims supported by the retrieved context / all claims |
| answer_relevancy | mean cosine(question, questions regenerated from the answer); 0 if noncommittal |
| context_precision | mean of precision@k over the ranks where the context was useful for the ground truth |
| context_recall | ground-truth sentences attributable to the retrieved context / all ground-truth sentences |

The LLM steps (claim extraction, support verdicts, question regeneration, usefulness,
attribution) sit behind one `Judge` interface: `LexicalJudge` for `--fake`, `LLMJudge` (structured
calls through `llm_gateway`) for `--provider`. The metric arithmetic is unit-tested with a
scripted judge in `tests/test_ragas_metrics.py`. One deliberate difference: RAGAS returns NaN
for an answer with no extractable claims; this mirror scores it 0.
